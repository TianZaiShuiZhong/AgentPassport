# v0.2 钱包身份与 Monad 测试网

## 对用户最简单的 Monad 接入方式

打开控制台右上角“网络与部署”，使用向导：

1. 复制显示的**本机测试钱包地址**，在 [官方水龙头](https://faucet.monad.xyz) 领取测试网 MON。若页面要求验证码，由用户完成。
2. 回到向导，点击右上角刷新，检查余额。
3. 点击“部署测试网合约”。项目使用本机生成的专用测试钱包支付测试网 gas，链 ID 必须为 10143，拒绝主网。
4. 等待真实部署确认，界面显示合约地址和交易链接。
5. 点击“启用 Monad 测试网”。服务检查合约版本和中继余额，保存 `.data/network.json`，通知启动器重启 Vault、两个应用及控制台。

向导不要求用户粘贴私钥。**本机测试钱包属于托管测试工具**，其私钥存在 `.data/keys.json`，不应当被称为用户非托管钱包。勿向该地址转入主网资产。实际测试网部署、激活和浏览器钱包弹窗仍需对应环境验证；仅完成代码不能当作已部署。

保留了 `npm run deploy:monad` 的手动部署方式。该方式使用 `.env` 的专用测试网私钥；与向导使用的测试钱包属于不同配置入口，选择其中一种管理部署即可。

## 用户自己拥有 Agent

“连接钱包”支持注入的 EIP-1193 钱包（例如 MetaMask / Rabby）：

1. 请求连接地址，再以 `personal_sign` 签署绑定域名、URI、链 ID、一次性 nonce 和过期时间的登录消息。
2. 登录只建立 30 分钟会话，**不注册 Agent，也不授权任何记忆**。
3. 点击“签名注册我的 Agent”，另行签署 EIP-712 注册意图。是否允许研究助手写入会在界面列出，并体现在签名的 `ingestor` 字段中。
4. 注册合约的 `owner` 和 `signer` 都是用户钱包。支付 gas 的中继不是 Agent 所有者。
5. 在研究助手中保存自己的上下文；加密正文和元数据按 Agent ID 绑定。默认演示记忆不会自动分享或复制到钱包工作空间。
6. 创建授权、批量撤销、启用/关闭研究写入权限都需要独立 EIP-712 钱包签名。登录消息不能用作授权。

本地链签名时钱包可能需要添加/切换到 AgentPassport Local EVM（1337）。签名不会花费用户钱包资金。未检测到浏览器钱包时，界面提示在安装了扩展的 Chrome/Edge 中打开 localhost；Codex 内嵌浏览器可能没有钱包扩展。

## 协议变化

- `registerFor`：验证用户注册意图，Agent 归签名钱包所有。
- `grantFor` / `revokeFor`：原子批量操作；签名绑定 Agent、应用、记忆/授权数组哈希、次数、期限和所有者 nonce。
- `updateIngestorFor`：用户控制独立的新增记忆权限。
- `commitMemoryFor`：已获写入权限的研究应用签署密文承诺；无法借此授权读取或管理其他 Agent。
- 所有 meta 操作使用独立的 `ownerNonces`，包含签名域中的链 ID 和合约地址。过期、重放、错误签名、跨 Agent 操作被拒绝。
- 钱包 Owner 预览要求该钱包的登录会话。演示管理员 token 不能预览钱包 Agent 的明文。

服务器的请求准备记录只保存结构化意图、元数据及期限；不会请求或接收用户钱包私钥。服务重启会清空登录会话和未提交的准备记录，需要重新登录/签名。

## 升级与持久化

v1 本地状态首次启动会部署 v2 合约。旧状态及加密 Vault 复制到 `.data/archive/v1-*`。记忆在内存中解密并为新链上下文重新加密，新密文承诺上链。迁移过程保存恢复指针；重启可继续尚未完成的记忆迁移。

旧合约及历史凭证保留，旧授权不自动搬到新部署。钱包工作空间和默认演示工作空间分开；独立应用链接携带 `agentId`。

## 已验证与尚待验证

自动化检查覆盖登录 nonce、错误签名、钱包实际所有权、所有者预览隔离、明确授权、批量签名、防重放、签名域、关闭研究写入、升级后数据保留及浏览器钱包完整流程。浏览器测试使用测试 EIP-1193 provider，不能替代真实钱包扩展与真实测试网 gas 验证。

Vault 仍然是可信密钥托管服务，尚非端到端加密。写作应用的签名密钥与本地应用会话仍由示例服务管理，虽然数据按 Agent 过滤，这不是完整的公网多租户安全架构。输出凭证仍为应用自检，未加入独立质量验证者或抗刷分声誉。
